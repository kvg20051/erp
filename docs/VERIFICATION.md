## Ребрендинг WAX

Название: wax; домен: wax.su. Новый слоган внесён в интерфейс, печатные PDF, Excel и документацию. Логотип обновлён встроенным image_gen. Служебные идентификаторы сохранены, см. [BRANDING.md](BRANDING.md).

После окончательных изменений повторно пройдены 10 интеграционных тестов на H2, включая HTTP/PDF/XLSX; собраны JAR и frontend. В браузере проверены вход, обзор, документы и персонал, обновлены снимки. Проверка PostgreSQL в таблице ниже относится к исходной версии до ребрендинга; в этой итерации она не повторялась.

## Автоматические сценарии

Исходник: [WorkflowTest.java](../backend/src/test/java/ru/nixu/WorkflowTest.java).

1. Закупка пяти серийных единиц, резерв трёх, частичный счёт/оплата, реализация и валовая прибыль.
2. Повтор Idempotency-Key и конфликт optimistic locking.
3. Согласование, закрытый период, неизменяемость проведённого документа.
4. Ограничение роли, юридического лица и чужого документа.
5. Откат всей транзакции при несуществующем серийном номере во второй строке.
6. Конкурентное списание одной единицы: проходит только одна операция.
7. Приём, маскирование персональных данных, отсутствие, табель/пакет 1С, блокировка при увольнении.
8. Выданное оборудование блокирует увольнение до возврата.
9. HTTP-вход, PDF, XLSX, дата и аудит отказа доступа.
10. Согласование списания по стоимости выбранного серийного экземпляра, а не средней стоимости других единиц.

## Не проверено и не следует считать готовым

- Docker daemon и Ansible отсутствуют в рабочей среде Windows: полный container build, ansible-playbook --syntax-check и реальный deploy здесь не выполнялись. Подготовлены команды и CI workflow, но GitHub CI не запускался и код не отправлялся в GitHub.
- Keycloak 26.8.2, HTTPS, ACME, Nginx, UFW, backup/restore проверены на уровне конфигурации, не на реальном VPS.
- Нет испытания 100k документов / 1M строк, 30 пользователей, SLA, RPO/RTO, отказа VM и двух API-реплик.
- Java/container vulnerability scanning не выполнен. Нулевой npm audit не означает отсутствие уязвимостей всей системы.
- UI smoke через самостоятельный Playwright-процесс был заблокирован средой запуска браузера Windows; интерактивная проверка выполнена через встроенный браузер. CI browser-smoke добавлен, но ещё не исполнен на GitHub.
- Файловый H2 после перезапуска в ограниченной среде Windows оказался доступен только для чтения. Поэтому браузерная проверка проведена на PostgreSQL; H2 в памяти прошла автоматические тесты.
- Frontend bundle около 1,32 МБ (около 412 КБ gzip); Vite сообщает предупреждение о размере. Нужны разделение bundle и измерение загрузки.
- Реальная эксплуатация с персональными данными не разрешается одной этой проверкой: политики хранения, уничтожение, RLS и прочие пробелы перечислены в REQUIREMENTS.md.

## Повторить проверку

~~~bash
# PostgreSQL test database must be dedicated: tests clear business tables!
export TEST_DB_URL=jdbc:postgresql://127.0.0.1:5432/nixu_test
export TEST_DB_USER=nixu_test
read -rs TEST_DB_PASSWORD
export TEST_DB_PASSWORD
mvn -f backend/pom.xml verify

cd apps/web
npm ci
npm run build
npm audit --audit-level=high
~~~

Без TEST_DB_URL тесты используют изолированную H2 в памяти.

~~~bash
pip install pyyaml jinja2
python3 scripts/validate_infra.py
~~~
