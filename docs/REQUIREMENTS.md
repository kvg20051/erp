# Матрица требований wax 0.1

**Домен портала:** [wax.su](https://wax.su)

**WAX — Workflows. Automation. eXecution.**

*Процессы. Автоматизация. Исполнение.*

«Прототип» означает реализованный механизм в этой поставке, а не полную промышленную приёмку. «Конфигурация» — подготовлен код настройки, но нет испытания на VPS. Полное соответствие fr.md и NFR.md не достигнуто.

## Функциональные требования

| ID | Требование | Статус | Реализация / оставшаяся работа |
|---|---|---|---|
| FR-COR-01 | Каждый документ имеет состояние: «Черновик», «На согласовании», «Проведён», «Отменён». Состав состояний конкретного документа может быть уже. | Прототип | Состояния и переходы DocumentService; WorkflowTest. |
| FR-COR-02 | Проведённый документ нельзя редактировать. Исправление выполняется отменой или корректирующим документом со ссылкой на исходный. | Частично | Проведённые записи неизменяемы; возвраты есть, универсальной корректировки/сторно нет. |
| FR-COR-03 | Документ получает номер автоматически. Нумерация ведётся отдельно по виду документа, юридическому лицу и году. | Прототип | Номер по виду, юрлицу и году; блокировка строки организации + UNIQUE. |
| FR-COR-04 | У документа есть дата документа (учётная) и технические отметки создания и изменения. | Прототип | DATE отдельно от технического времени; Dates нормализует API. |
| FR-COR-05 | Документы можно создавать на основании других документов с переносом данных. | Частично | Одно основание и цепочка; объединение нескольких заявок отсутствует. |
| FR-COR-06 | К документу и карточке справочника можно прикрепить файлы. | Частично | Файлы к документам; нет вложений справочников и S3. |
| FR-COR-07 | К документу можно добавлять комментарии. | Прототип | Добавление с автором/временем; редактирование комментариев не предоставлено. |
| FR-COR-08 | У документа и карточки справочника есть история изменений. | Частично | Аудит действий есть, полные before/after и UI истории карточки отсутствуют. |
| FR-COR-09 | Списки поддерживают поиск, фильтры, сортировку и постраничный вывод. | Частично | Документы: серверные страницы, фильтры, поиск номера; остальные списки ограничены, сортировка фиксирована. |
| FR-COR-10 | Любой список и отчёт можно выгрузить в Excel и CSV. | Частично | CSV/XLSX только сотрудники, остатки, прибыль. Нет фоновых массовых выгрузок. |
| FR-COR-11 | Документы имеют печатную форму в PDF. | Частично | Универсальный PDF; банковские реквизиты и согласованные специализированные шаблоны не завершены. |
| FR-COR-12 | Пользователь получает уведомления о событиях, требующих его действия. | Частично | Событие в outbox; нет email, адресного inbox и доставки. |
| FR-COR-13 | Пользователь, работающий с несколькими юридическими лицами, выбирает, от какого из них создаёт документ. | Прототип | Организация проверяется сервером для объектов, файлов и отчётов. |
| FR-COR-14 | При одновременном редактировании одного объекта второй пользователь получает сообщение о конфликте. | Прототип | Версии документов и карточек, HTTP 409. |
| FR-COR-15 | На главной странице пользователь видит свои задачи. | Частично | Обзор документов/согласований; персональная маршрутизация задач отсутствует. |
| FR-COR-16 | Документ можно оформить в иностранной валюте. | Частично | Курсы, суммы, фиксация в документе; в UI нет даты последнего известного курса и полного рублёвого представления. |
| FR-COR-17 | Учётный период закрывается по юридическому лицу. | Прототип | Закрытие/открытие периода на юрлицо, проверки на сервере и аудит. |
| FR-MDM-01 | Записи справочников можно создавать, изменять и просматривать в пределах прав. | Частично | Типизированные справочники с общими карточками; не все реквизиты и формы реализованы. |
| FR-MDM-02 | Запись, которая используется в документах, нельзя удалить; её можно пометить как недействующую. | Прототип | Удаления нет; active=false исключает выбор новых записей. |
| FR-MDM-03 | Система предупреждает о возможных дубликатах. | Не реализовано | Предупреждения по совпадению ИНН/КПП ещё нет. |
| FR-MDM-04 | Обязательные реквизиты и форматы проверяются при сохранении. | Частично | ИНН: длина/контрольные числа. КПП: формат (контрольного числа у КПП нет). Остальные проверки неполны. |
| FR-MDM-05 | Справочники можно загружать из файла CSV или Excel. | Частично | CSV сотрудников с построчным отчётом и пропуском существующих кодов; общего CSV/XLSX импорта нет. |
| FR-MDM-06 | У контрагентов, номенклатуры и сотрудников есть поле внешнего идентификатора. | Частично | externalId сохраняется в данных; отдельный поиск не реализован. |
| FR-MDM-07 | Номенклатура объединяется в группы. | Частично | Группа/parent сохраняются; дерево и фильтрация по поддереву отсутствуют. |
| FR-MDM-08 | Ставка НДС в документе подставляется из номенклатуры и действует на дату документа. | Частично | Ставка текущей номенклатуры фиксируется; история ставок по датам отсутствует. |
| FR-MDM-09 | Курсы валют вводятся вручную или загружаются из файла. | Частично | Ручные курсы, выбор последнего известного; нет импорта и предупреждения об устаревании. |
| FR-ACL-01 | Администратор создаёт, изменяет и блокирует учётные записи пользователей. | Частично | Бизнес-grant создаётся/блокируется в ERP; identity отдельно в Keycloak. |
| FR-ACL-02 | Права задаются ролями. Роль — набор разрешений вида «модуль, объект, действие». | Частично | Фиксированные роли; произвольных наборов объект/действие нет. |
| FR-ACL-03 | Доступ пользователя ограничивается перечнем юридических лиц. | Прототип | Проверка org в сервисах и SQL, тест прямого API; RLS ещё нет. |
| FR-ACL-04 | Доступ можно ограничить областью данных: свои документы, документы своего подразделения, все документы. | Частично | Свои документы/карточка для employee; подразделения руководителя не изолированы. |
| FR-ACL-05 | Система поставляется с набором ролей из раздела 3. | Частично | Есть стартовые роли; инициатор использует employee, конструктора ролей нет. |
| FR-ACL-06 | Доступ к персональным данным сотрудников выдаётся отдельным разрешением. | Прототип | Паспорт, адрес, телефон, дата рождения маскируются в карточке и выгрузках без pii. |
| FR-ACL-07 | Вход выполняется по логину и паролю; для администраторов обязателен второй фактор. | Конфигурация | Keycloak OIDC/PKCE + обязательный OTP; реальный вход на VPS не испытан. Восстановление через email требует SMTP. |
| FR-ACL-08 | Администратор просматривает журнал аудита. | Частично | Просмотр последних 300 событий; runtime-role без UPDATE/DELETE на VPS, нет фильтров/архива. |
| FR-ACL-09 | Изменения прав фиксируются в аудите. | Прототип | Назначение/блокировка grants записываются в аудит, без полного before/after. |
| FR-ACL-10 | Пользователь может назначить заместителя на период отсутствия. | Не реализовано | Заместители и делегирование согласований отсутствуют. |

| FR-PUR-04 | Заказ поставщику выше заданной суммы проходит согласование. | Прототип | Порог 1000 USD, конвертация и настраиваемая политика организации. |

| FR-PUR-07 | К поступлению прикладываются документы поставщика. | Частично | Вложения есть; отдельные номер/дата документа поставщика не оформлены. |
| FR-PUR-08 | По заказу ведётся отметка оплаты. | Частично | Идемпотентные частичные оплаты и контроль переплаты; сводный статус оплаты не вычисляется. |
| FR-PUR-09 | Оформляется возврат поставщику. | Прототип | Возврат по поступлению и расход со склада. |

| FR-PUR-11 | Хранится история цен поставщиков. | Не реализовано | Отдельной истории/подсказки цен нет. |
| FR-PUR-12 | Доступны отчёты по закупкам. | Частично | Фильтры списка; специализированные закупочные отчёты не реализованы. |

| FR-SAL-02 | Ведутся прайс-листы с периодом действия. | Частично | Карточки прайс-листа хранятся; автоподстановка не реализована. |

| FR-SAL-05 | По заказу оформляется реализация: полная или частичная. | Прототип | Частичная реализация с проверкой остатков/резервов/серийных номеров. |
| FR-SAL-06 | Товар можно зарезервировать под заказ клиента. | Прототип | Резерв, снятие, потребление при отгрузке; тест конкурентного списания. |
