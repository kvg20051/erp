# Функциональные требования к ERP-системе. Фаза 1

**Версия:** 0.3
**Дата:** 14 ноября 2026 года
**Статус:** проект для согласования
**Основание:** `README.md` (модули), `ARCHITECTURE.md` (архитектура), `NFR.md` (нефункциональные требования), `STACK.md` версии 0.4 (стек и фазы), `employees.csv` (пример данных сотрудников)

## 1. Назначение и границы

Документ описывает, что система должна уметь к концу фазы 1. Как быстро, надёжно и безопасно она должна это делать, определяет `NFR.md`.

### В фазу 1 входит

| Код | Модуль | Раздел |
|---|---|---|
| `MDB001` | Единая база данных: общие механизмы документов | 4 |
| `MDM002` | Справочники (НСИ) | 5 |
| `ACL003` | Права доступа | 6 |
| `PUR102` | Закупки | 7 |
| `SAL103` | Продажи | 8 |
| `WHS104` | Склад и запасы | 9 |
| `HRM203` | Персонал | 10 |

Клиент фазы 1 — веб-интерфейс на русском языке.

### В фазу 1 не входит

- Мобильное приложение (фаза 2).
- Интеграция с 1С (фаза 3). До неё бухгалтерский учёт ведётся в 1С отдельно.
- Модули `FIN101`, `CTL201`, `MFG202`, `SCM204`, `CRM205`, `PRJ206`, `EAM207`, `QMS208`, `BIA209`.
- Бухгалтерские проводки, налоговая отчётность, счета-фактуры и УПД: они оформляются в 1С.
- Расчёт зарплаты: ведётся в 1С. В фазе 1 есть только заглушка обмена (FR-HRM-18).
- Курсовые разницы и переоценка валютных остатков: учитываются в 1С.
- Автоматическая загрузка курсов валют из внешних источников.
- Перенос исторических данных: остатков, открытых заказов, сотрудников.
- Сборка серверов из комплектующих и учёт гарантийных обращений.
- Включение дополнительных расходов (доставка, таможенные платежи) в себестоимость.
- Ввод начальных остатков: на момент запуска товара на складе нет.
- Регулярное выставление счетов по подпискам.
- Интеграции с банками, ЭДО и другими внешними системами.
- Настраиваемые многошаговые маршруты согласования.

## 2. Принятые решения и допущения

### Принятые решения

| № | Решение |
|---|---|
| 1 | Компания продаёт готовые серверы и не собирает их из комплектующих. Основной поток — закупка, хранение и продажа оборудования. |
| 2 | Зарплата считается в 1С. Пока интеграции нет, в `HRM203` стоит заглушка обмена. |
| 3 | Документы в иностранной валюте нужны и в закупках, и в продажах. |
| 4 | Себестоимость запасов считается в фазе 1: для серийных позиций по фактической цене конкретной единицы, для остальных по средней скользящей в пределах юридического лица. Метод совпадает с учётной политикой в 1С. Дополнительные расходы в себестоимость пока не включаются. |
| 5 | Согласование одношаговое. Порог суммы при запуске — 1000 долларов США; значение меняется в настройках. |
| 6 | Утверждённых шаблонов печатных форм нет; система поставляется с собственными. |
| 7 | Первый отчёт для руководства — список сотрудников. |
| 8 | Исторические данные в систему не переносятся. |
| 9 | Все сведения карточки сотрудника обязательны. Сроки хранения данных сотрудников определяются законом о персональных данных и правилами хранения кадровых документов. |
| 10 | На момент запуска товара на складе нет. |
| 11 | Учёт гарантийных обращений не нужен, достаточно срока гарантии. |

### Допущения

Приняты там, где ответа пока нет. Вопросы по ним собраны в разделе 13.

| № | Допущение |
|---|---|
| 1 | Каждый сервер учитывается по серийному номеру. |
| 2 | Валюта учёта — рубль. Курсы валют вводятся вручную или загружаются из файла. |
| 3 | Порог согласования применяется к заказам поставщикам и к списаниям. Заявки на закупку согласуются всегда. |
| 4 | Отрицательные остатки запрещены. |
| 5 | Оплаты вносятся вручную как отметки к документам, так как связи с банком и 1С нет. |
| 6 | В системе несколько юридических лиц; каждый документ принадлежит одному из них (`NFR.md`, раздел 2). |

## 3. Роли пользователей

Роли — стартовый набор. Администратор может менять состав прав каждой роли (раздел 6).

| Роль | Что делает |
|---|---|
| Администратор | Управляет пользователями, ролями и настройками, просматривает аудит |
| Ответственный за справочники | Ведёт справочники и разбирает дубликаты |
| Инициатор закупки | Создаёт заявки на закупку и видит их состояние |
| Менеджер по закупкам | Оформляет заказы поставщикам и поступления |
| Менеджер по продажам | Оформляет заказы клиентов, счета и реализации |
| Кладовщик | Оформляет складские документы и проводит инвентаризацию |
| Специалист по персоналу | Ведёт карточки сотрудников, кадровые события, отсутствия и табель |
| Руководитель | Согласует документы, видит отчёты по своему подразделению |
| Сотрудник | Видит свои данные, подаёт заявки на отсутствие, видит выданное ему оборудование |

## 4. Общие механизмы документов (`MDB001`)

Требования действуют для всех документов фазы 1, если в разделе модуля не сказано иное.

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-COR-01 | Каждый документ имеет состояние: «Черновик», «На согласовании», «Проведён», «Отменён». Состав состояний конкретного документа может быть уже. | Для каждого вида документа описаны состояния и разрешённые переходы; недопустимый переход отклоняется с понятным сообщением. |
| FR-COR-02 | Проведённый документ нельзя редактировать. Исправление выполняется отменой или корректирующим документом со ссылкой на исходный. | Попытка изменить проведённый документ отклоняется; у корректирующего документа видна связь с исходным (NFR-D05). |
| FR-COR-03 | Документ получает номер автоматически. Нумерация ведётся отдельно по виду документа, юридическому лицу и году. | Два документа одного вида и юридического лица не получают одинаковый номер, в том числе при одновременном создании. |
| FR-COR-04 | У документа есть дата документа (учётная) и технические отметки создания и изменения. | Учётную дату задаёт пользователь; технические отметки ставит система и изменить их нельзя (NFR-D08). |
| FR-COR-05 | Документы можно создавать на основании других документов с переносом данных. | Заказ создаётся из заявки, поступление из заказа и так далее; в цепочке видны все связанные документы. |
| FR-COR-06 | К документу и карточке справочника можно прикрепить файлы. | Файл загружается, просматривается и скачивается; доступ к файлу определяется правами на его документ (NFR-S02). |
| FR-COR-07 | К документу можно добавлять комментарии. | Комментарий сохраняет автора и время; изменить чужой комментарий нельзя. |
| FR-COR-08 | У документа и карточки справочника есть история изменений. | Видно, кто, когда и что изменил, включая смену состояния. |
| FR-COR-09 | Списки поддерживают поиск, фильтры, сортировку и постраничный вывод. | Список из 100 000 документов открывается и фильтруется без загрузки всех записей в браузер (NFR-P05). |
| FR-COR-10 | Любой список и отчёт можно выгрузить в Excel и CSV. | Выгрузка содержит те же строки и столбцы, что видит пользователь с учётом фильтров и прав. Большие выгрузки формируются в фоне (NFR-P04). |
| FR-COR-11 | Документы имеют печатную форму в PDF. | Печатные формы фазы 1: заявка на закупку, заказ поставщику, заказ клиента, счёт на оплату, складские документы, акт инвентаризации. Утверждённых шаблонов у компании нет, поэтому формы разрабатываются в проекте и согласуются по образцам. |
| FR-COR-12 | Пользователь получает уведомления о событиях, требующих его действия. | Уведомление в интерфейсе и по электронной почте приходит согласующему при поступлении документа и автору при решении по нему. |
| FR-COR-13 | Пользователь, работающий с несколькими юридическими лицами, выбирает, от какого из них создаёт документ. | В списках доступен фильтр по юридическому лицу; данные недоступных юридических лиц не показываются (NFR-S01). |
| FR-COR-14 | При одновременном редактировании одного объекта второй пользователь получает сообщение о конфликте. | Изменения первого пользователя не теряются; второй видит, что объект изменён, и может повторить правку (NFR-D03). |
| FR-COR-15 | На главной странице пользователь видит свои задачи. | Показаны документы, ожидающие его согласования, его черновики и последние уведомления. |
| FR-COR-16 | Документ можно оформить в иностранной валюте. | В документе указаны валюта и курс на дату документа; суммы показываются в валюте и в рублях. Курс подставляется из справочника и после проведения не меняется. |
| FR-COR-17 | Учётный период закрывается по юридическому лицу. | В закрытом периоде нельзя провести, изменить или отменить документ; попытка отклоняется, в том числе через API (NFR-D06). Закрытие и открытие периода фиксируются в аудите. |

## 5. Справочники (`MDM002`)

### Состав справочников

| Справочник | Основные сведения |
|---|---|
| Юридические лица | Наименование, ИНН, КПП, адрес, реквизиты |
| Подразделения | Наименование, юридическое лицо, вышестоящее подразделение, руководитель |
| Должности | Наименование |
| Контрагенты | Наименование, тип (поставщик, клиент), ИНН, КПП, адреса, контактные лица, банковские реквизиты |
| Договоры | Контрагент, юридическое лицо, номер, дата, срок действия, тип (закупка, продажа) |
| Номенклатура | Наименование, вид (товар, услуга, лицензия или подписка), единица измерения, ставка НДС, признак учёта по серийным номерам, гарантийный срок |
| Валюты | Код, наименование |
| Курсы валют | Валюта, дата, курс к рублю |
| Единицы измерения | Наименование, краткое обозначение |
| Ставки НДС | Значение, период действия |
| Склады | Наименование, юридическое лицо, ответственный |

### Требования

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-MDM-01 | Записи справочников можно создавать, изменять и просматривать в пределах прав. | Для каждого справочника из таблицы выше есть список и карточка. |
| FR-MDM-02 | Запись, которая используется в документах, нельзя удалить; её можно пометить как недействующую. | Недействующая запись не предлагается при выборе в новых документах, но остаётся в старых. |
| FR-MDM-03 | Система предупреждает о возможных дубликатах. | При создании контрагента с уже существующим ИНН и КПП показывается предупреждение со ссылкой на найденную запись. |
| FR-MDM-04 | Обязательные реквизиты и форматы проверяются при сохранении. | ИНН и КПП проверяются по длине и контрольному числу; ошибка указывает поле и способ исправления (NFR-U02). |
| FR-MDM-05 | Справочники можно загружать из файла CSV или Excel. | После загрузки доступен отчёт о принятых и отклонённых строках с причинами; повторная загрузка того же файла не создаёт дубликаты (NFR-I04). |
| FR-MDM-06 | У контрагентов, номенклатуры и сотрудников есть поле внешнего идентификатора. | Поле заполняется вручную или при загрузке, доступно в поиске и выгрузке. Оно понадобится для сопоставления с 1С в фазе 3. |
| FR-MDM-07 | Номенклатура объединяется в группы. | Группы образуют иерархию; по группе работают фильтры в списках и отчётах. |
| FR-MDM-08 | Ставка НДС в документе подставляется из номенклатуры и действует на дату документа. | При смене ставки с определённой даты новые документы получают новую ставку, старые не меняются. |
| FR-MDM-09 | Курсы валют вводятся вручную или загружаются из файла. | Курс хранится на каждую дату. Если курса на дату документа нет, система предлагает последний известный и показывает его дату. |

## 6. Права доступа (`ACL003`)

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-ACL-01 | Администратор создаёт, изменяет и блокирует учётные записи пользователей. | Заблокированный пользователь теряет доступ не позднее чем через 5 минут (NFR-S09). |
| FR-ACL-02 | Права задаются ролями. Роль — набор разрешений вида «модуль, объект, действие». | Действия: просмотр, создание, изменение, проведение, отмена, согласование, выгрузка. Пользователь может иметь несколько ролей. |
| FR-ACL-03 | Доступ пользователя ограничивается перечнем юридических лиц. | Пользователь не видит документы, отчёты и вложения юридических лиц, к которым не допущен, в том числе по прямой ссылке (NFR-S01, S02). |
| FR-ACL-04 | Доступ можно ограничить областью данных: свои документы, документы своего подразделения, все документы. | Руководитель видит документы своего подразделения; сотрудник — только свои. |
| FR-ACL-05 | Система поставляется с набором ролей из раздела 3. | Администратор может менять разрешения ролей и создавать новые роли. |
| FR-ACL-06 | Доступ к персональным данным сотрудников выдаётся отдельным разрешением. | Без разрешения паспортные данные, адрес и телефон не видны ни в карточке, ни в отчётах, ни в выгрузках. |
| FR-ACL-07 | Вход выполняется по логину и паролю; для администраторов обязателен второй фактор. | Администратор не может войти без второго фактора (NFR-S03). Пользователь может сам сменить пароль и восстановить доступ. |
| FR-ACL-08 | Администратор просматривает журнал аудита. | Доступны фильтры по пользователю, объекту, действию и периоду. Изменить или удалить запись журнала нельзя (NFR-S07, S08). |
| FR-ACL-09 | Изменения прав фиксируются в аудите. | По журналу видно, кто, когда и какие роли или разрешения выдал или отозвал. |
| FR-ACL-10 | Пользователь может назначить заместителя на период отсутствия. | Документы на согласование в этот период приходят заместителю; назначение фиксируется в аудите. |

## 7. Закупки (`PUR102`)

Цепочка документов: заявка на закупку → заказ поставщику → поступление.

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-PUR-01 | Сотрудник создаёт заявку на закупку: позиции, количество, желаемый срок, обоснование. | Позиция выбирается из номенклатуры или описывается текстом, если нужной записи ещё нет. |
| FR-PUR-02 | Заявка проходит согласование. | Согласующий утверждает или отклоняет заявку с комментарием; автор получает уведомление. Согласующий определяется по подразделению автора. |
| FR-PUR-03 | Менеджер по закупкам создаёт заказ поставщику на основании одной или нескольких согласованных заявок. | В заказе указаны поставщик, договор, валюта, позиции, цены, ставки НДС, срок поставки и условия оплаты. Суммы без НДС, НДС и итог считаются автоматически (NFR-D04). |
| FR-PUR-04 | Заказ поставщику выше заданной суммы проходит согласование. | Порог при запуске — 1000 долларов США; он задаётся в настройках по юридическому лицу. Сумма заказа в другой валюте пересчитывается в валюту порога по курсу на дату документа. Заказ ниже порога проводится без согласования. |
| FR-PUR-05 | По заказу оформляется поступление: полное или частичное. | Поступление товаров создаёт приход на склад (раздел 9). Поступление услуг и подписок оформляется без складского движения. |
| FR-PUR-06 | Система показывает исполнение заказа. | По каждой позиции видно: заказано, получено, осталось. Заказ закрывается автоматически при полном получении или вручную с указанием причины. |
| FR-PUR-07 | К поступлению прикладываются документы поставщика. | Сканы накладной, акта или счёта хранятся как вложения; номер и дата документа поставщика записываются в поступление. |
| FR-PUR-08 | По заказу ведётся отметка оплаты. | Пользователь вносит дату и сумму оплаты; заказ показывает состояние: не оплачен, оплачен частично, оплачен. |
| FR-PUR-09 | Оформляется возврат поставщику. | Возврат создаётся на основании поступления и уменьшает остаток на складе. |
| FR-PUR-10 | Для подписок и лицензий хранится срок действия. | Система уведомляет ответственного за заданное число дней до окончания срока. |
| FR-PUR-11 | Хранится история цен поставщиков. | При выборе позиции в заказе видны последняя цена и поставщик по этой позиции. |
| FR-PUR-12 | Доступны отчёты по закупкам. | Отчёты: заявки по состояниям, заказы в работе и просроченные, закупки по поставщикам, номенклатуре и подразделениям за период, неоплаченные заказы. |

## 8. Продажи (`SAL103`)

Цепочка документов: заказ клиента → счёт на оплату → реализация.

## 11. Сквозные сценарии для приёмки

Каждый сценарий проходится целиком, разными пользователями с соответствующими ролями.

### Сценарий 1. Закупка серверов в валюте

1. Менеджер по закупкам создаёт заказ поставщику на пять серверов в долларах на сумму выше 1000 долларов; заказ уходит на согласование.
2. Руководитель согласует заказ.
3. Кладовщик оформляет поступление и вводит серийные номера.
4. Остаток на складе увеличивается на пять серверов; у каждого своя себестоимость в рублях по курсу на дату поступления; заказ закрывается.

### Сценарий 2. Продажа серверов с частичной оплатой

1. Менеджер по продажам создаёт заказ клиента на три сервера в долларах и резервирует их.
2. Формирует счёт на оплату на половину суммы и печатает его.
3. Вносит отметку оплаты; счёт получает состояние «Оплачен», заказ — «Оплачен частично».
4. Кладовщик оформляет реализацию с серийными номерами; остаток уменьшается, резерв снимается.
5. Отчёт о валовой прибыли показывает выручку в рублях по курсу на дату реализации, себестоимость именно этих трёх серверов и прибыль.
6. По серийному номеру находится клиент и дата окончания гарантии.

### Сценарий 3. Приём и увольнение сотрудника

1. Специалист по персоналу создаёт карточку и оформляет приём.
2. Создаётся учётная запись; сотрудник входит в систему и видит свои данные.
3. Сотрудник подаёт заявку на отпуск; руководитель согласует её; табель отражает отпуск.
4. Специалист формирует табель за месяц; пакет для 1С появляется в очереди обмена и скачивается файлом.
5. Специалист оформляет увольнение; обходной лист показывает невозвращённый ноутбук.
6. После возврата оборудования увольнение завершается; учётная запись блокируется; карточка видна в отчёте «Список сотрудников» с состоянием «Уволен» только пользователю с доступом к архиву персонала.
7. Для записи с истёкшим сроком хранения ответственный подтверждает уничтожение; персональные поля очищаются, формируется акт.

### Сценарий 4. Разграничение доступа

1. Пользователь с доступом к одному юридическому лицу не видит документы другого, в том числе по прямой ссылке.
2. Пользователь без разрешения на персональные данные не видит паспорт сотрудника ни в карточке, ни в выгрузке.
3. Попытка изменить проведённый документ отклоняется.
4. Все перечисленные попытки и действия видны администратору в журнале аудита.

## 12. Замечание по `employees.csv`

Файл принят как образец формата для FR-HRM-04. В нём нет отчества, полной даты рождения, должности, подразделения и даты приёма. Раз все сведения карточки обязательны (FR-HRM-01), загруженные из такого файла карточки останутся с пометкой «Не заполнена», пока данные не внесут вручную или не расширят формат файла.

Перенос сотрудников из других систем не планируется, поэтому загрузка из файла — вспомогательная функция, а не обязательный шаг запуска.

Данные в файле выглядят тестовыми. Реальные данные сотрудников в репозиторий попадать не должны (NFR-S06).
